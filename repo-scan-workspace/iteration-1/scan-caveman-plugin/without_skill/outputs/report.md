## Overview

"caveman" is a multi-agent AI productivity plugin/skill that makes LLM coding assistants respond in ultra-compressed, caveman-style prose. The primary goal is reducing output token usage by ~65-75% while preserving full technical accuracy. It supports Claude Code, Codex, Gemini CLI, Cursor, Windsurf, Cline, GitHub Copilot, and 40+ other AI coding agents via `npx skills`.

## How It Works

### Core mechanism
On every Claude Code session start, `hooks/caveman-activate.js` (a SessionStart hook) emits the full caveman ruleset as hidden system context injected by Claude Code. This avoids users needing to type anything. The hook also writes a flag file at `~/.claude/.caveman-active` that a statusline badge script reads.

The `UserPromptSubmit` hook (`caveman-mode-tracker.js`) watches for `/caveman` commands and updates the flag file to reflect the current intensity level (lite / full / ultra / wenyan variants).

### Compress sub-skill
`caveman-compress` is a Python CLI that sends a memory file to the Claude API (or `claude --print` as fallback), compresses its natural language prose into caveman-style, validates that code blocks, URLs, headings, and file paths are unchanged, and retries targeted fixes up to 2 times before giving up and restoring the original.

### Skill distribution
The CI workflow (`sync-skill.yml`) auto-propagates `skills/caveman/SKILL.md` to every agent-specific location on push to `main`. This single-source-of-truth design prevents copy/paste drift across the 10+ target locations.

## Potential Issues

### Testing gaps
- `tests/test_hooks.py` covers only the install/uninstall/activate JavaScript hooks (4 tests). There are **no Python unit tests** for the compress scripts (`compress.py`, `validate.py`, `detect.py`). The `tests/caveman-compress/` directory holds only static fixture files used for manual comparison, not automated test assertions.
- `tests/verify_repo.py` exists but its contents were not analyzed in detail; likely a structural integrity check rather than a full test suite.
- There is no test runner configuration (`pytest.ini`, `pyproject.toml`, `tox.ini`, `Makefile`), so tests must be run manually (`python -m unittest tests/test_hooks.py`).

### No CI for tests
The only GitHub Actions workflow is `sync-skill.yml`, which syncs files but does **not run any tests**. There is no CI test pipeline. If the hooks or compress scripts break, no automated check will catch it before release.

### No Python packaging
The compress scripts are structured as a package (`scripts/`) but there is no `pyproject.toml`, `setup.py`, or `requirements.txt` in `caveman-compress/` itself. Users must know to run `python3 -m scripts` from within `caveman-compress/` or the plugin skills directory. This is documented in the SKILL.md but is a usability friction point.

### Benchmark results directory is empty
`benchmarks/results/` contains only a `.gitkeep`. The README states results are committed, but no actual result JSON files are present in this cached copy. This may be intentional (results are large) or indicate the benchmarks have not been run against the current skill version.

### `anthropic` SDK optional in compress scripts
`compress.py` gracefully falls back to the `claude` CLI if the `anthropic` package is not installed. However, the `benchmarks/run.py` script imports `anthropic` unconditionally at the top level and will fail at startup without it.

### CI commits directly to `main`
`sync-skill.yml` pushes auto-generated file changes directly to `main` using `[skip ci]`. This bypasses any branch protection or review process for synced files, which is a minor governance concern.

### SECURITY.md false-positive note
The repo includes a `caveman-compress/SECURITY.md` acknowledging that Snyk flags the compress scripts as "High Risk" due to subprocess/file I/O patterns. The maintainer states this is a false positive. Users running security scanners in CI may need to suppress this finding.

## Summary

Caveman is a well-structured, lightweight plugin with a clear single-source-of-truth architecture enforced by CI sync. The core hook system (JavaScript) is dependency-free and robustly designed with silent-fail error handling throughout. The compress sub-skill (Python) is the most complex component and has solid validation logic but lacks automated tests. The primary gaps are: no CI test pipeline, no Python unit tests for the compress scripts, and no Python packaging metadata.
